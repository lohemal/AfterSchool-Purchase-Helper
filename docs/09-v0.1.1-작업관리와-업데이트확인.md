# v0.1.1 — 작업 관리와 업데이트 확인

v0.1.0 을 실제로 쓰면서 드러난 두 가지를 고친 판이다.

1. **작업 이름을 사용자가 정할 수 없었다.** 프로그램이 지어 준 이름 하나뿐이라
   같은 달에 작업을 둘 만들면 목록에서 구별이 안 됐다.
2. **업데이트를 확인할 길이 없었다.** 켤 때 조용히 한 번 확인하지만,
   새 버전이 없으면 아무 말도 하지 않으므로 「확인은 된 건가」를 알 수 없었다.

기존 업무 규칙·DB 구조·검증 원칙은 **하나도 바꾸지 않았다.**

---

## 1. 무엇을 바꿨나

| | v0.1.0 | v0.1.1 |
|---|---|---|
| 새 작업 | 단추를 누르면 `2026학년도 9월 교재비` 로 바로 만들어졌다 | **이름을 고쳐 넣고** 만든다 |
| 이름 바꾸기 | 없다 | 있다. **작업 id 는 그대로** |
| 작업 지우기 | 없다 (서버에는 있었지만 화면에 단추가 없었다) | 있다. 한 번 더 묻는다 |
| 업데이트 | 켤 때 조용히 자동 확인만 | 자동 확인은 그대로 + **직접 누르는 확인** |

## 2. 작업 구조 — 무엇을 건드렸고 무엇을 안 건드렸나

작업 하나에 딸린 자료는 전부 `work_id` 로 매달려 있다.

```
work (id, title, school_year, month, kind, …)
 ├─ work_quote            견적서 1장 = 품의 1행
 │   └─ work_quote_item   추출한 품목 줄 (raw_* 는 원문 그대로)
 ├─ work_settlement_row   정산자료 한 줄
 ├─ work_allocation       거래처별 재원 배분
 ├─ work_check            검증 결과와 확인 사유
 └─ work_output           만든 Excel 기록
```

**딸린 자료는 `title` 을 전혀 보지 않는다.** 전부 `work_id` 만 본다.
그래서 이름을 바꾸는 일은 `work.title` 한 칸을 고치는 것으로 끝난다.
견적서·추출 결과·정산·매핑·배분·검증·생성 기록은 손댈 필요가 없다.

### 마이그레이션은 없다

표를 하나도 더하거나 고치지 않았다. 자료 구조 번호(`PRAGMA user_version`)는
v0.1.0 과 같은 **2** 그대로다. 그래서 v0.1.0 이 쓰던 DB 를 v0.1.1 이 열 때
**아무 일도 일어나지 않는다** — 마이그레이션도, 백업 복사도 돌지 않는다.

이 약속이 깨지지 않도록 시험으로 못을 박아 두었다
(`db/crud_tests.rs :: schema_is_unchanged_since_v0_1_0`).
나중에 표를 바꾸면 이 시험이 먼저 깨지면서 "마이그레이션을 만들어라"라고 알려 준다.

## 3. 작업명 — 만들 때와 바꿀 때가 같은 규칙

규칙은 한 곳에 모았다.

```rust
// domain/work.rs
fn clean_title(title: &str) -> AppResult<&str> {
    let t = title.trim();
    if t.is_empty() {
        return Err(AppError::new("WORK_TITLE_EMPTY", "작업 이름을 입력해 주세요."));
    }
    Ok(t)
}
```

`create_work` 와 `rename_work` 가 **둘 다** 이 함수를 지난다.
한쪽만 막으면 이름 없는 작업이 목록에 남아 고를 수조차 없게 된다.

화면에도 같은 규칙이 있다(`src/lib/workName.ts`). 화면은 미리 알려 주기 위한 것이고,
**실제로 지키는 쪽은 서버다.**

> 한글 입력에서는 전각 공백(`　`)이 잘 섞인다.
> JavaScript 의 `trim()` 과 Rust 의 `str::trim()` 은 둘 다 이것을 공백으로 보므로
> 양쪽 판단이 어긋나지 않는다. 시험에서 이 글자를 따로 확인한다.

### 이름을 바꿔도 id 는 안 바뀐다

```rust
pub fn rename_work(conn: &Connection, id: i64, title: &str) -> AppResult<()> {
    let t = clean_title(title)?;
    let n = conn.execute(
        "UPDATE work SET title = ?2, updated_at = ?3 WHERE id = ?1", …)?;
    if n == 0 { return Err(AppError::new("WORK_NOT_FOUND", "작업을 찾을 수 없습니다.")); }
    Ok(())
}
```

`UPDATE` 한 줄이다. `INSERT` + `DELETE` 로 옮겨 담는 방식은 쓰지 않는다 —
그러면 id 가 바뀌어 딸린 자료가 전부 고아가 된다.

## 4. 작업 지우기 — SQLite 가 정확히 그것만 치운다

```rust
pub fn delete_work(conn: &Connection, id: i64) -> AppResult<()> {
    let n = conn.execute("DELETE FROM work WHERE id = ?1", [id])?;
    …
}
```

한 줄로 끝나는 까닭은 표를 만들 때부터 이렇게 묶어 두었기 때문이다.

```sql
work_id INTEGER NOT NULL REFERENCES work(id) ON DELETE CASCADE
```

`work_quote` · `work_settlement_row` · `work_allocation` · `work_check` · `work_output`
다섯이 모두 `work(id)` 에 매여 있고, `work_quote_item` 은 다시 `work_quote(id)` 에 매여 있다.
그래서 **두 단계까지 따라 내려가며** 그 작업 것만 지워진다.

이 정리는 연결을 열 때 켜 두는 설정 하나에 기대고 있다.

```rust
conn.pragma_update(None, "foreign_keys", "ON")?;   // db/mod.rs :: setup_conn
```

이 설정이 꺼지면 딸린 자료가 **고아로 남는다.** 그래서 켜져 있는지 자체를
시험으로 확인한다(`foreign_keys_are_on`).

### 원본 파일은 건드리지 않는다

견적서 원본은 처음부터 복사하지 않고 **경로만** 적어 둔다(설계안 14장 15번).
만들어 둔 Excel 도 사용자가 고른 폴더에 있다. 작업을 지울 때
그 경로가 적힌 줄만 사라지고 **파일은 그대로 남는다.**
시험 `delete_never_touches_the_original_files` 가 파일이 실제로 남아 있는지 확인한다.

### 되돌릴 수 없으므로 한 번 더 묻는다

```
'방과후 9월 교재비' 작업을 삭제하시겠습니까?
작업에 포함된 견적서, 정산 및 배분 자료도 함께 삭제됩니다.

            [취소]  [삭제]

원본 견적서 파일과 만들어 둔 Excel 은 지우지 않습니다.
```

## 5. 화면에서 `window.prompt` 를 쓰지 않는 까닭

이 앱은 Windows 의 WebView2 위에서 돈다. **WebView2 에는 `prompt` 가 없다.**
부르면 오류도 없이 `null` 이 돌아와서, 이름을 물어본 줄 알았는데 아무 일도 안 일어난다.

그래서 이름 칸과 삭제 확인을 **화면 안에 직접 그렸다**(`components/WorkPicker.tsx`).
덤으로 삭제 확인을 여러 줄로 또렷하게 보여 줄 수 있게 됐다.

입력칸은 기존 `TextField` 를 그대로 쓴다 — 한글 조합이 깨지지 않는 그 컴포넌트다.

## 6. 업데이트 확인

### 자동 확인은 그대로 둔다

`UpdateBanner` 는 손대지 않았다. 켜고 3초 뒤에 조용히 한 번 확인하고,
없으면 아무 말도 하지 않고, 실패해도 조용히 넘어간다. 시작을 막지 않는다.

### 직접 누르는 확인을 더했다

설정 화면(`부서 설정`) **맨 위**에 **프로그램 정보** 한 줄을 만들었다.

```
프로그램 정보  v0.1.1   [업데이트 확인]   현재 최신 버전입니다.
```

처음에는 화면 맨 아래에 두었는데, 실제로 설치해 보니 **부서가 스무 개쯤 되면
한참 굴려 내려야 닿았고 글이 화면 끝에 걸려 잘렸다.** 맨 위로 옮겼다.
스크롤과 상관없이 늘 보이고, 설정 화면을 열면 바로 눈에 들어온다.

네 가지 결과를 **모두 말로** 보여 준다.

| 상태 | 문장 |
|---|---|
| 확인 중 | 업데이트를 확인하고 있습니다. |
| 최신 | 현재 최신 버전입니다. |
| 새 버전 | 새 버전 v0.1.2을 사용할 수 있습니다. |
| 실패 | 업데이트 정보를 확인하지 못했습니다. |

### 지키는 것 셋

**① 실패가 앱 전체 오류로 번지지 않는다.**
`check()` 와 `install()` 은 어떤 경우에도 예외를 밖으로 던지지 않는다.
인터넷이 없어도 품의 작성은 전부 된다. 오류 내용(주소·경로)을 화면 문구에
옮기지도 않는다 — 사용자가 할 수 있는 일이 없고, 로그 규칙에도 어긋난다.

**② 두 번 눌러도 요청은 한 번이다.**
확인은 몇 초 걸린다. 단추를 흐리게 하는 것만으로는 모자라다
(자동 확인과 사용자 확인이 겹칠 수 있다). 확인기 안에 잠금을 두어
돌고 있는 동안 들어온 요청은 흘려보낸다.

**③ 서명 검증을 돌아가지 않는다.**
내려받기와 서명 확인은 전부 Tauri 업데이터가 한다.
따로 내려받거나 확인을 건너뛰는 길은 만들지 않았다.
**v0.1.0 에 박혀 있는 공개 키와 짝인 서명 키를 그대로 쓴다.**

판단 규칙은 화면에서 떼어 순수 함수로 두었다(`src/lib/updateCheck.ts`).
Tauri 를 부르는 부분만 따로 얇게 감쌌다(`src/lib/tauriUpdate.ts`).
그래서 브라우저 없이 시험할 수 있다.

## 7. 버전 선언을 다섯 곳 모두 본다

v0.1.0 때는 세 곳(`package.json` · `tauri.conf.json` · `Cargo.toml`)만 맞췄다.
잠금 파일 둘에도 이 프로그램 **자신의** 버전이 적혀 있다.

| 자리 |
|---|
| `package.json` |
| `package-lock.json` (두 곳 — 뿌리와 `packages[""]`) |
| `src-tauri/tauri.conf.json` |
| `src-tauri/Cargo.toml` |
| `src-tauri/Cargo.lock` (이 프로그램 항목만) |

목록을 `scripts/version-files.mjs` 한곳에 모아
`check-version` 과 `set-version` 이 **같은 목록**을 보게 했다.
한쪽만 알고 있으면 「맞췄는데 시험이 통과하지 않는」 일이 난다.

```bash
npm run version:set 0.1.1
npm run check:version
```

## 9. 기존 기능이 깨지지 않았는지

v0.1.0 의 자동 시험을 그대로 전부 돌렸다. 바꾼 것이 작업 이름 한 칸과
화면 두 군데뿐이라, 견적서 읽기·추출·정산·배분·검증·생성 경로에는
손이 닿지 않았다.

| | |
|---|---|
| Rust `cargo test --lib` | 174건 통과 · 0 실패 (14건은 한글/샘플 필요로 건너뜀) |
| Node `npm run check:model` | 전부 통과 |
| `npm run build` (타입 검사) | 통과 |
| `cargo clippy --lib -- -D warnings` | 경고 0 |
| `npm run check:version` | 다섯 곳 모두 0.1.1 |
| `npm run check:public` | 막을 것 0건 |

업데이트 서명 키는 **바꾸지 않았다.** `tauri.conf.json` 의 `pubkey` 는
v0.1.0 과 글자 하나까지 같다(`git diff` 로 확인).

| 삭제 확인 | 작업명과 함께 무엇이 사라지는지 보여 주고 `취소`·`삭제` 를 준다 |
| 프로그램 정보 | 화면 맨 위에 `v0.1.1` 과 `업데이트 확인` |

> 화면 확인은 **취소만 눌렀다.** 실제 업무 자료가 든 DB 에 아무것도 쓰지 않았다.
> 확인 뒤 다시 읽어 줄 수가 하나도 달라지지 않은 것을 확인했다.

## 11. 짚고 넘어갈 것 — 저장소가 Private 이면 업데이터가 닿지 못한다

`업데이트 확인` 을 눌렀더니 **「업데이트 정보를 확인하지 못했습니다.」** 가 나왔다.

까닭을 확인했다.

```
https://github.com/lohemal/AfterSchool-Purchase-Helper/releases/latest/download/latest.json
→ 익명 접근 HTTP 404
```

저장소가 **Private** 이라 로그인하지 않은 요청에는 릴리스 파일이 보이지 않는다.
Tauri 업데이터는 로그인 없이 이 주소를 부르므로 **언제나 404** 를 받는다.

### v0.1.0 때는 왜 몰랐나

자동 확인(`UpdateBanner`)은 **실패해도 아무 말도 하지 않는다.** 일부러 그렇게 만들었다.
그래서 v0.1.0 을 설치하고 「알림이 안 뜬다」를 보았을 때
「같은 버전이라 안 뜬다」로 읽었지만, 사실은 **확인 자체가 실패**하고 있었을 수 있다.
둘을 구별할 방법이 없었다. 이번에 직접 누르는 확인을 만들자 바로 드러났다.

### 정하고 가야 할 것

| 길 | 뜻 |
|---|---|
| 저장소를 Public 으로 | Tauri 업데이터가 그대로 작동한다. 소스가 공개된다 |
| Private 유지 | **자동 업데이트를 쓸 수 없다.** 새 버전은 설치 파일을 직접 받아 깐다 |

토큰을 넣은 주소를 쓰는 길도 있지만 **앱 안에 토큰을 박아야 해서** 쓰지 않는다.
설치 파일을 뜯으면 누구나 그 토큰을 꺼낼 수 있다.

이것은 **사용자가 정할 일**이라 여기서 바꾸지 않았다.
`v0.1.0 → v0.1.1` 실제 업데이트 시험은 이 결정 뒤에 해야 한다.

## 12. 공개 직전에 잡은 것 — 안전 검사기가 `docs/` 를 통째로 건너뛰고 있었다

저장소를 Public 으로 바꾸기 직전, `npm run check:public` 을 다시 돌리다가
**검사기가 한글 이름 파일을 하나도 읽지 않고 있었다**는 것을 발견했다.

```js
execSync('git ls-files').split('\n')
```

`git ls-files` 는 `core.quotepath` 가 켜져 있으면(기본값) ASCII 가 아닌 이름을
**따옴표에 넣고 8진수로 이스케이프해서** 내놓는다.

```
"docs/08-P5-\353\260\260\355\217\254\354\244\200\353\271\204.md"
```

이 문자열로 파일을 열면 당연히 없는 파일이고, 그 자리는

```js
try { text = readFileSync(f, 'utf8') } catch { continue }
```

가 **아무 말 없이 삼켰다.** 그리고 끝에서는 `검사한 파일 ${files.length}개` 를 찍었다 —
목록에 있는 개수이지 읽은 개수가 아니다. 그래서 「185개 검사, 막음 0건」으로 보였다.

실제로 빠진 것은 `docs/` 아홉 개 **전부**였다.
그중에는 예전에 실제 거래처 사업자등록번호와 대표자 성명이 적혀 있던
`docs/02-샘플분석및설계검증.md` 도 있다.

### 세 군데를 고쳤다

| 고친 것 | 왜 |
|---|---|
| `git ls-files -z` 로 바꾸고 `\0` 로 나눈다 | `-z` 는 이스케이프하지 않는다 |
| 읽지 못한 파일을 **막음으로 센다** | 검사하지 못한 것은 통과가 아니다 |
| **읽은 개수와 건너뛴 개수를 따로 세어 목록 수와 맞춰 본다** | 또 조용히 빠지면 숫자가 어긋나 드러난다 |

```
목록 185개 (Git 추적 대상)
  내용을 읽은 파일 134개 · 형식상 건너뛴 파일 51개
  막음 0건 · 살핌 25건
```

### 다시 검사한 결과

고친 검사기로 돌리니 **살핌이 15건에서 25건으로 늘었다.** 늘어난 10건이 `docs/` 것이다.
하나하나 확인한 결과 **전부 가명화를 설명하는 문장**이었다.

| 걸린 것 | 실제 내용 |
|---|---|
| `대표자 성명이 걸렸고` (`01-설계안.md`) | 예전에 걸렸다는 **기록** |
| `대표자 성명 \| 0건` (`08-P5`) | 검사 결과 **표** |
| `대표자 성명·주소·전화가 모두 채워져 있다` (`02-샘플`) | 바로 뒤에 "실제 값은 개인정보라 여기 옮겨 적지 않는다" |
| `상상바둑` · `프로보테크닉` | 거래처 이름. 가명화 대상이 아니라고 이미 판단해 둔 것 |

**사업자등록번호·주민등록번호·전화번호·학교 이름은 `docs/` 어디에도 없다.**

### Git history 도 따로 훑었다

Public 이 되면 **과거 커밋도 누구나 본다.** 그래서 두 가지를 더 했다.

**① 모든 블롭을 같은 기준으로** (`git rev-list --objects --all`, 블롭 161개)
걸린 것은 `docs/08-P5-배포준비.md` 의 옛 판 셋뿐이었고,
내용은 「검사기 자신이 들고 있는 낱말 목록이 걸렸다」를 적은 **문장**이었다.
그 줄을 `BEGIN …PRIVATE KEY` 로 고쳐 지금 판은 걸리지 않는다.
(옛 판에 남은 것은 그 **문구**일 뿐 키가 아니다.)

**② 진짜 키와 비밀번호를 손에 들고 블롭 207개와 직접 대조**했다.
→ **한 번도 들어간 적이 없다.** 그러므로 v0.1.0 에서 쓴 key pair 를 그대로 쓴다.

한 번이라도 들어갔다면 그 키는 버려야 했고,
그러면 v0.1.0 에서 v0.1.1 로 가는 자동 업데이트 자체가 불가능했을 것이다.

### 덧붙여 — 저장소에 추가된 적 있는 경로 전체

`git log --all --diff-filter=A --name-only` 로 **한 번이라도 추가된 경로**를 모았더니
185개였고, 지금 추적 중인 파일 수와 **정확히 같다.**
넣었다 지운 파일이 하나도 없다는 뜻이다.
`test/fixtures-local/` · `test/out/` · `*.db` · `*.key` 는 history 에 들어간 적이 없다.
