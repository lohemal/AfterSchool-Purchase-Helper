## 2. 화면

1. **부서 설정** — 왼쪽 부서 목록, 오른쪽에 품의 부서 / 정산 별칭 / 거래처 관리 단위 세 칸.
   별칭 칸과 거래처 칸에 "무엇에 쓰는 이름인지" 를 각각 적어 두어 섞이지 않게 했다.
2. **견적서 등록** — 파일 고르기, 자동 매칭 결과와 이유, 거래처 드롭다운, 상태.
3. **추출 결과 확인** — 품목 표에 **품의 표시명과 원문이 함께** 보이고 고친 줄에는 되돌리기 단추가 생긴다.
   행 종류(일반 품목 / 할인·조정 / 금액 0원)와 할인 부호를 고를 수 있고, 합계 상자와 비교 기준, 대표품목, 문구가 한 화면에 있다.
4. **정산자료 등록** — 부서별 합산 결과와 읽어 온 원본을 함께 보여 준다. 미등록 별칭은 빨강으로 띄우고 그 자리에서 부서에 붙인다.
5. **금액 배분·검증** — 부서마다 격자 하나. 거래처가 하나면 값이 잠긴 채 자동으로 차고, 여럿이면 직접 넣는다.
   **세로(재원별)와 가로(거래처별) 검증이 타이핑하는 즉시** 갱신된다. 아래에 확인이 필요한 항목과 사유 칸.
6. **품의자료 미리보기** — 재원 탭 4개. 0원 재원은 "대상 금액 없음 · 파일 생성 안 함".
7. **Excel 생성** — 잠금 상태와 이유, 저장 폴더, 만들어질 이름, 생성 결과와 폴더 열기.

## 3. DB 구조

`PRAGMA user_version` = 1. 표 11개 (설계안 4장 그대로).

```
설정   department · settlement_alias · vendor_unit · setting
작업   work · work_quote · work_quote_item · work_settlement_row
       work_allocation · work_check · work_output
```

- 금액은 전부 **원 단위 정수**. 소수를 쓰지 않는다.
- `work_quote_item` 은 `raw_name / raw_spec / raw_qty / raw_unit_price / raw_amount` 를 따로 들고 있고
  **어떤 편집에도 덮어쓰지 않는다.** 사용자가 고치는 것은 `display_name` 등 별도 칸이다.
- 원본 견적서는 복사하지 않는다. `source_path · source_size · source_hash` 만 둔다.
- `settlement_alias.alias` 와 `vendor_unit.mgmt_name` 은 **다른 표**다. 매칭 후보에는 거래처만 넣는다.

## 4. 지원 형식

| 형식 | 상태 |
|---|---|
| XLSX · XLS · XLSM | 읽는다 |
| HWPX | 읽는다 |
| HWP | 읽는다 (한글 설치 필요. 없으면 화면 위에 안내하고 직접 입력으로 넘어간다) |
| 정산자료 XLSX | 읽는다 |
| 에듀파인 XLSX | 만든다 |
| PDF | **P2** — 등록은 되고 "직접 입력 필요" 로 표시된다 |

**못 읽는 형식 때문에 작업이 멈추지 않는다.** 등록·거래처 매칭은 그대로 되고 품목만 손으로 넣으면 된다.

## 5. 자동 시험 결과

```
cargo test --lib                                99 passed · 0 failed · 2 ignored
cargo test --lib -- --ignored --test-threads=1   2 passed (한글 COM 필요)
npm run check:model                              check-match · check-phrase · check-allocation 통과
npm run build                                    tsc --noEmit + vite build 통과
cargo build                                      경고 없음
```

주요 시험:

- **매칭**(설계안 14장 1번) — 파일명 형식이 달라도 같게 맞고, 거래처가 여럿이면 **추측하지 않는다**.
  정산 별칭이 후보에 없다는 것도 시험으로 못 박았다.
- **문구**(6-6) — 로봇과학·주산암산 두 건이 사람이 실제로 쓴 문구와 **글자까지 같다**.
- **행 종류**(6-2) — 할인·0원 행이 `N종`·대표품목에서 빠지고, 할인은 총액에 들어가며 0원 행은 안 들어간다.
  할인 부호는 검산으로 정하고 모르면 0으로 두고 경고한다. 원문은 어느 경우에도 그대로다.
- **배분**(9장) — 거래처 하나면 옮기기, 둘이면 자동 배분이 **없다**. 세로·가로가 각각 어긋난 자리를 짚는다.
- **차단**(14장 13번) — 공란 사유로는 풀리지 않고, 일부만 확인하면 여전히 막힌다.
- **생성**(10장) — 실제 업로드 샘플과 **셀 80개가 값·자료형·표시형식·글꼴·색·정렬·네 방향 테두리까지 일치**.

## 8. 남은 제한

- **PDF·사진 견적서는 못 읽는다.** 등록과 거래처 매칭은 되고 품목은 직접 넣어야 한다(P2·P3).
- **HWP 는 한글이 깔린 PC 에서만** 읽힌다. 없으면 화면 위에 안내가 뜬다.
- 견적서 안의 상호는 **참고로만** 보여 준다. 매칭에 쓰지 않는다.
- 열 너비는 라이브러리 한계로 샘플과 0.07 문자 다르다(P0-1 에서 도달 불가 확인). 값·자료형·서식은 같다.
  **실제 업로드에는 지장이 없음이 확인됐다.**
- 배포(태그·Release·서명)는 하지 않았다. P1 범위가 아니다.

## 10. 사용자가 직접 확인할 한글 입력 (IME)

진짜 Windows 한국어 IME 조작은 자동으로 재현할 수 없다(`05-한글입력-수정.md` 7장).
아래를 **한/영 키로 직접 쳐서** 확인해 주세요. 붙여넣기 말고 타자로 쳐야 의미가 있습니다.

**꼭 봐야 할 곳 — 추출 결과 확인 화면**

1. 품목의 **품의 표시명** 칸에 `방과후 기초Yap! 상` 을 친다 → 그대로 들어가는지
2. 같은 칸에 `드론항공과학 교구세트` · `바둑교재(상상바둑)` · `토탈공예미니어처`
3. **규격** 칸에 `권` 을 친다
4. 한글을 치다가 **Backspace** 로 지우고 다시 친다
5. 한글 → 영문 → 숫자 → 기호를 섞어 친다 (예: `교재A-1 (2026)본`)
6. 빠르게 연속으로 친다
7. 다 친 뒤 **다른 칸을 눌러** 옮긴다 → 그때 저장된다 (치는 동안에는 저장되지 않는 것이 정상)
8. **품의 내용 문구** 칸에도 한글을 쳐 본다
9. 다른 견적서를 골랐다가 돌아왔을 때 값이 그대로인지
10. 앱을 **끄고 다시 켜서** 같은 글자가 남아 있는지

**함께 봐 주실 곳**

- 부서 설정: 품의 부서명 · 품의 표기명 · 정산 별칭 · 거래처 관리명 · 거래처 이름
- 금액 배분·검증: **확인 사유** 칸 (한글을 치면 「확인함」 단추가 바로 켜지는지)
- 수량·단가·금액 칸에 숫자를 치는 동작이 예전과 같은지

> 달라진 점 하나: 이제 **칸을 벗어날 때 저장**됩니다. 값을 고치고 바로 다른 화면으로 넘어가지 말고,
> 다른 칸을 한 번 누르거나 Enter 를 눌러 주세요. (합계와 문구가 그때 갱신됩니다.)
